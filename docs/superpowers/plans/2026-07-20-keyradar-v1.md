# KeyRadar v1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development
> or executing-plans to implement this plan task-by-task. Behavioral work uses
> test-driven development.

**Goal:** Ship KeyRadar v1.0 as a production-ready, public, zero-telemetry
Windows hotkey ownership and conflict diagnostic application.

**Architecture:** A C# WinUI 3 app consumes UI-independent Core, Rules, and
Windows services. Native x64/x86 helpers are isolated behind a targeted deep
observation interface. An independent updater replaces verified portable files.

**Tech stack:** .NET 10 LTS, Windows App SDK 2.2, WinUI 3, C++/Win32 helpers,
xUnit, JSON Schema, GitHub Actions and GitHub Releases.

---

## Delivery sequence

1. Bootstrap the public repository, toolchain, solution, CI, documentation, and
   a high-fidelity KeyRadar visual companion.
2. Build tested domain types, gesture normalization, evidence merging, and
   conflict classification.
3. Build signed rule-pack validation, safe declarative readers, storage modes,
   import/export, and rollback.
4. Build process/window inventory, global registration probing, foreground
   watching, UI Automation, and privacy-safe passive matching.
5. Build the WinUI 3 main inventory and non-activating foreground window.
6. Build targeted x64/x86 deep observation with timeout and optional elevation.
7. Add Windows knowledge and the approved 50 application profiles.
8. Build GitHub program/rule updates, diagnostics, signing, rollback, and release
   automation.
9. Pass unit, integration, privacy, performance, Windows-version, architecture,
   packaging, and WeChat Alt+A acceptance gates before publishing v1.0.0.
