# KeyRadar v1.0.0 Windows 实际占用优先扫描规格

状态：实现中；本文按当前实现同步，首次 `v1.0.0` Release 尚未创建

日期：2026-07-20

本文档补充并修订 `2026-07-20-keyradar-v1-schema-v2-ui-design.md`。发生冲突
时，以本文档的扫描顺序、运行应用范围、硬件映射和深度确认定义为准。

## 一、产品定位

KeyRadar 是仅支持 Windows 10/11 的热键占用与归属诊断工具。默认扫描先形成
“当前可操作/可归属热键清单”，再使用本机配置、用户声明的硬件 Profile、
Windows 系统知识和正式规则补充归属。完整标准全局组合探测仍保留为诊断证据，
而不是普通界面的原始日志。

软件不得只把在线规则表当成当前结果。探测到占用但无法安全归属时，也必须
显示“已占用 · 归属未知”。

产品文案不得承诺“扫描全部热键”，统一表述为：

> 显示当前可发现的全局组合占用、运行中应用的本机配置、当前硬件映射及
> 已知 Windows 应用内热键；无法可靠归属的项目明确标记为未知。

## 二、安全和隐私原则

- 仅处理当前 Windows 桌面会话中的运行应用、系统状态、标准全局组合和
  当前硬件映射。
- 默认不模拟、不发送、不注入、不拦截、不吞掉任何按键。
- 用户正常使用热键时，原功能必须照常执行。
- 不记录普通文字输入、聊天内容、完整窗口标题、宏文本、账号、用户名或
  未授权路径。
- 不进行全盘配置搜索，只访问已支持应用声明的白名单位置。
- 未取得可靠证据时，只能显示未知、可能或无法确认。
- 快速扫描、规则匹配、本机配置读取和标准全局组合探测不向其他进程注入
  DLL。
- 不安装服务、不创建计划任务、不驻留后台；关闭后2秒内全部组件退出。

## 三、扫描管线

用户点击扫描后按以下顺序执行：

1. 枚举当前前台、后台和托盘常驻应用，以及当前连接硬件。
2. 读取 Windows 版本、当前输入法、截图工具和已知系统热键状态。
3. 分批探测候选标准全局组合当前是否可注册。
4. 只对正在运行的应用执行 Schema v2 规则匹配。
5. 只读取正在运行且已支持应用的白名单本机热键设置。
6. 识别当前连接硬件与相关管理软件；厂商 Profile 没有安全公开读取接口时只报告
   “无法安全读取”，不伪造实时映射。用户导入的脱敏声明式 Profile 可作为可能证据。
7. 按最新扫描时间并使用确定性并列规则合并占用、配置、硬件、系统和规则证据；
   每个规范化热键只发布一行，并保留未知项。

扫描支持取消和进度报告，不阻塞 UI。用户开始输入、桌面被锁定、切换桌面
或进入安全桌面时，立即暂停或取消标准全局组合探测。取消或未完成扫描不能发布
部分 UI 状态，也不能替换最近一次完整扫描的导出快照。

## 四、当前运行状态

扫描内容包括：

- 前台窗口所属进程；
- 后台窗口、后台进程和托盘常驻程序；
- 进程名、临时路径、版本、签名发布者、完整性级别和 x86/x64 架构；
- 当前连接 HID 键盘、鼠标的厂商、型号和连接状态；
- G HUB、Logi Options+、Razer Synapse 和 Corsair iCUE 等硬件软件是否运行；
- Windows 版本、输入法和截图工具状态。

完整进程路径只允许在内存中用于白名单判断，不得写入规则、日志或诊断。

应用规则和配置读取以“当前正在运行”为前提。未运行的 Photoshop、VS Code
等应用不显示，也不参与当前冲突判断。

普通清单的分组顺序为：

1. 当前前台应用；
2. 当前生效硬件 Profile；
3. 正在后台运行的应用；
4. Windows 系统热键；
5. 已占用但归属未知的组合。

应用的范围还受当前前后台状态限制：后台运行的应用只可纳入全局或后台范围的
热键；应用内热键只有在该应用处于前台时才纳入。Windows 系统热键按系统范围
单独纳入。

## 五、标准全局组合占用探测

默认扫描包含一个基于 `RegisterHotKey` 的占用探测器。每个候选组合按以下
过程处理：

1. 确认当前没有物理按键处于按下状态，并满足短暂输入空闲门槛。
2. 使用当前扫描专用的隐藏消息窗口和唯一 ID 调用 `RegisterHotKey`。
3. 注册成功时，在 `finally` 中立即调用 `UnregisterHotKey`，结果为
   `AvailableAtScanTime`。
4. 错误为 `ERROR_HOTKEY_ALREADY_REGISTERED` 时，结果为 `Occupied`。
5. 系统保留、Windows 组合或不支持时，结果为 `SystemReserved`。
6. 其他失败结果为 `ProbeError`，保留 Win32 错误码。
7. 探测器不处理 `WM_HOTKEY`，不发送或模拟候选组合。

候选生成规则：

- Ctrl、Alt、Shift 及其组合，搭配字母、数字、F1–F24、导航键、
  PrintScreen、媒体键和浏览器键；
- 无修饰键时，仅生成 F1–F24、媒体键、浏览器键等非文字功能键；
- 不生成裸字母和裸数字；
- Win 组合以 Windows 系统规则为主，探测结果仅作为参考；
- 永远排除 Ctrl+Alt+Del 等安全注意序列。

每条结果至少包含：

```text
gesture
availability = Occupied | AvailableAtScanTime | SystemReserved | ProbeError
mechanism = RegisterHotKeyProbe
owner = Unknown
scannedAtUtc
win32ErrorCode（可选）
```

`AvailableAtScanTime` 只说明扫描瞬间可注册，不代表永久可用。

原始探测与普通清单必须分离：

- `AvailableAtScanTime`、`SystemReserved` 和 `ProbeError` 不作为仅由探测产生的普通行；
- 仅有 `RegisterHotKey` 占用证据的裸 `F1`–`F24`、浏览器、媒体、音量、启动和导航键
  不作为普通行；
- `PrintScreen` 和带修饰键的组合仍可进入普通清单；
- 所有候选（包括被普通界面隐藏的项目）保留在经过清洗的 Schema v2 诊断
  `probeTelemetry` 中。

## 六、本机应用配置

只对当前运行且规则声明了白名单读取器的应用访问本机设置。读取器必须限定
注册表键、已知设置文件或 UI Automation 目标，不接受规则包提供任意路径。

证据优先级为：

1. 本机配置已发现；
2. 当前硬件映射已发现；
3. Windows 系统已知；
4. 官方默认规则；
5. 多来源交叉佐证；
6. 疑似归属；
7. 归属未知。

本机实际设置始终优先于官方默认规则。多个运行应用只命中规则而没有本机
配置证据时，显示全部候选和“可能冲突”，不得选择其中一个作为确定归属。

## 七、硬件映射

硬件相关信息在普通清单中可形成独立“当前设备与 Profile”分组。当前只识别
以下管理软件和匹配设备：

- Logitech G HUB；
- Logi Options+；
- Razer Synapse；
- Corsair iCUE。

当前实现读取已连接设备的厂商、型号和连接状态，并识别管理软件是否正在运行。
它不会解析未公开、私有或加密的厂商数据库，因此不能实时读取当前 Profile、层、
板载槽位或映射。用户可显式导入经校验与脱敏的声明式 JSON；导入项始终标为
“用户声明 · 未实时验证”，只能作为可能证据，不能冒充确定归属。

物理键本身通常不参与标准组合冲突，映射出的组合或宏序列参与。宏必须标记
为“宏序列”，不得伪装为单一热键；宏文本、路径、账号和敏感参数默认不读
取。板载映射不能安全读取时显示“设备板载映射 · 无法读取”；当前只支持导入
用户声明配置，不提供当前槽位的实时选择或读取。

## 八、证据合并与冲突

同一标准化组合只显示一个结果，聚合所有证据，不重复堆叠。

例如微信运行、本机配置包含 `Alt+A → 截图`，用户导入的 G HUB Profile 的 G2
声明映射到 `Alt+A`，且 RegisterHotKey 探测为占用时，结果显示：

- 功能和应用：微信 · 截图；
- 状态：本机配置已发现；
- 范围：全局；
- 冲突：G HUB 用户声明的 G2 映射为 Alt+A；
- 证据：微信本机配置、运行进程、用户声明 Profile 和占用探测。

探测到占用但没有其他证据时，显示：

- `Alt+A`；
- 状态：已占用；
- 归属：未知；
- 证据：RegisterHotKey 占用探测；
- 操作：深度确认、导出诊断。

## 九、点击即运行的深度确认

深度确认只用于单条已占用但归属未知或证据不足的组合。点击后立即执行，
不得要求用户再按一次组合，也不显示保存工作之类的二次操作提示。

流程：

1. 不请求 UAC，也不承诺读取管理员进程内部的热键归属；Windows 没有该安全公开
   接口。管理员目标应保留为无法确认或未知。
2. 在辅助组件可用时，按需要启动对应架构的 x64/x86 定向复核组件；缺失或失败时
   仅使用受管复核并明确标示限制。
3. 立即复核目标组合的 RegisterHotKey 占用状态。
4. 重新执行运行进程关联、支持应用本机配置、已导入的用户声明硬件 Profile、Windows
   系统规则及当前前后台规则匹配。
5. 生成结论并立即卸载全部观察组件。

结论仅允许：

- 已确认归属：当前本机配置精确命中；实时硬件 Profile 读取当前未实现，用户声明
  Profile 不足以确认归属；
- 可能归属：运行应用规则吻合但无本机配置证据；
- 已占用，归属未知：标准全局探测确认占用但无安全归属证据；
- 无法确认：私有 Hook、Raw Input、驱动、权限或板载宏等原因。

Windows 没有公开 API 能在不触发热键的前提下直接返回标准热键注册进程。
因此纯未知占用必须保持未知。深度确认绝不自动模拟用户组合。

## 十、必须标示的盲区

以下内容必须显示“无法完整发现”或“未知”，不能承诺完整覆盖：

- 低级键盘 Hook；
- Raw Input 和 DirectInput；
- 游戏反作弊和驱动层拦截；
- 私有、加密或云端配置；
- 无安全读取方式的板载宏；
- 浏览器扩展、插件、脚本和游戏 Mod；
- 多键序列；
- 依赖对话框、模式、会议状态或焦点的上下文热键；
- 未运行应用的热键。

## 十一、UI 与验收

普通清单的每条结果至少展示：

- 标准组合或物理硬件键；
- 功能；
- 应用或未知；
- 范围：全局、应用内、硬件映射或 Windows 系统；
- 状态：可归属证据或已占用；仅探测到“扫描瞬间可注册”、系统保留或探测错误的
  项目保留到诊断，不作为普通行；
- 可信度：本机配置已发现、已确认、官方默认、交叉佐证、疑似或未知；
- 配置、硬件 Profile、规则来源和扫描时间证据；
- 适用操作：打开设置、深度确认或导出诊断。

“转到应用”仍遵守已确认的应用 Tag 设计，只在应用标题层展示一次。

必须通过：

- Alt+A 被占用但无法归属时显示“已占用 · 归属未知”。
- 微信运行且本机读取到 Ctrl+L 时显示“微信 · 锁定 · 本机配置已发现”。
- 用户导入的 G HUB G2 声明映射 Alt+A、微信当前配置 Alt+A 时显示可能冲突，
  不将导入项说成实时读取的确定冲突。
- 未运行应用不进入当前列表或冲突计算。
- 默认扫描和深度确认都不触发任何用户热键。
- 点击深度确认后直接完成复核，不等待再次按键。
- 纯未知标准组合保持未知，不虚构进程名。
- 扫描可取消、UI 不冻结、所有临时注册保证释放。
- 取消扫描不发布部分结果；诊断导出只读取最近一次完整扫描的单一快照。
- 裸 F1–F24、浏览器、媒体、音量、启动和导航键如只有 RegisterHotKey 占用证据，
  不显示为普通行；PrintScreen 与带修饰键的组合按正常规则处理。
- `AvailableAtScanTime`、`SystemReserved`、`ProbeError` 与普通界面隐藏探测项均可在
  Schema v2 `probeTelemetry` 中诊断。
- 日志和诊断不包含普通文字按键流、用户名、完整窗口标题、宏文本或未授权
  路径。
